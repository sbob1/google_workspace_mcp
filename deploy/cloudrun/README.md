# Seanbob Ventures — Workspace MCP on Cloud Run

Source of truth for how this fork is deployed. Everything here follows
<https://workspacemcp.com/docs/deployment> unless noted.

## What runs where

| Piece | Value |
|---|---|
| Google Cloud project | `seanbob-ventures` (org: seanbobventures.com) |
| Cloud Run service | `workspace-mcp`, `us-central1` |
| MCP endpoint | `https://workspace-mcp-459981624154.us-central1.run.app/mcp` |
| OAuth client | "Claude Workspace MCP" — Web application, **agentic**, Internal consent screen |
| OAuth client secret | Secret Manager: `workspace-mcp-client-secret` |
| JWT/storage key | Secret Manager: `workspace-mcp-jwt-key` (generated by `setup.sh`, never displayed) |
| Sign-in session store | `gs://seanbob-ventures-mcp-sessions`, mounted at `/data/oauth-proxy`, Fernet-encrypted |
| Download staging | `gs://seanbob-ventures-mcp-files`, objects deleted after 1 day |

## Design choices

- **Stateless mode** (`WORKSPACE_MCP_STATELESS_MODE=true`): no local file writes and no
  long-lived HTTP sessions, so the server can scale to zero.
- **Session store on a Cloud Storage mount**: the docs list memory, disk, or Valkey.
  We use `disk` on a GCS FUSE mount so sign-ins survive restarts without paying for
  Valkey. Safe because `max-instances=1` keeps a single writer. *Not covered by the
  upstream docs — verify after any upstream upgrade.*
- **Only seanbobventures.com accounts** can sign in: enforced by the Internal consent
  screen (the server has no domain allowlist of its own).
- **Client registration** limited to Claude and Claude Code callback URLs.
- **Tools off at launch**: see [Tools turned off](#tools-turned-off) below.
- **Cost guard**: scale to zero, max 1 instance, $4 Cloud Run spend cap and $5 project
  budget alert (set in the Billing console).

## Tools turned off

These upstream tools are hidden from Claude via `WORKSPACE_MCP_DISABLED_TOOLS` in
`env.yaml` (decided Oct 2026). They're the main ways a malicious email or doc could
trick an agent into leaking data or acting outside your review.

| Tool | Service | What it does | Why it's off |
|---|---|---|---|
| `manage_drive_access` | Drive | Grant, update, or revoke sharing for people/groups; transfer file ownership | Could share files outside seanbobventures.com |
| `set_drive_file_permissions` | Drive | Change link sharing, e.g. "anyone with the link" | Could make files public |
| `run_script_function` | Apps Script | Execute a function in a deployed script, as you | A script runs with your full access and can bypass the other limits |
| `manage_deployment` | Apps Script | Create, update, or delete script deployments | Needed to publish scripts that `run_script_function` executes |

Still on: Apps Script editing (`manage_script_project`, `manage_script_content`, …),
Gmail filters (`manage_gmail_filter`; the server can't add new forwarding addresses),
and read-only sharing checks (`get_drive_file_permissions`, `check_drive_file_public_access`).

**To turn one back on:** remove it from `WORKSPACE_MCP_DISABLED_TOOLS` in `env.yaml`,
then run `bash deploy/cloudrun/deploy.sh`. No reconnect needed — the OAuth scopes are
already granted. Idea for later: patch Drive sharing to allow seanbobventures.com only.

## First-time setup (Cloud Shell)

```bash
git clone https://github.com/sbob1/google_workspace_mcp.git
cd google_workspace_mcp
bash deploy/cloudrun/setup.sh    # service accounts, buckets, IAM, JWT key
bash deploy/cloudrun/deploy.sh   # build + deploy
```

Then in Claude: Settings → Connectors → Add custom connector →
`https://workspace-mcp-459981624154.us-central1.run.app/mcp`.

## Updating

- **Config change** (e.g. tools on/off): edit `env.yaml`, run `deploy.sh`.
- **Upstream update**: GitHub "Sync fork", review the diff, run `deploy.sh`.
  Our changes are confined to `deploy/cloudrun/` and one line in `Dockerfile`.

## Off switches

- Pause: Cloud Run → `workspace-mcp` → set max instances to 0 (or delete the service).
- Revoke Google access: myaccount.google.com → Security → third-party access.
